# 串連社群、產業和政府

很多公司和政府機關早就在使用開源軟體，內部也有熟悉開源社群的工程師。問題是，這些經驗常常只留在個人身上。想回報問題、貢獻程式碼，或把內部工具開放出來時，組織裡未必有共同流程，也不一定知道誰能做決定。

OCF 今天在東京舉辦的 OSPOlogy Asia 2026，分享我們如何串連開源社群、企業與政府。OSPOlogy 是 Linux Foundation 推動開源辦公室 OSPO（Open Source Program Office）交流的活動，這次是第一次在亞洲舉辦。

「辦公室」容易讓人想到在組織內正式成立單位，並有明確的負責人、政策和工作範圍。然而，要在組織內部直接成立一個辦公室來管理開源事務，實屬不易。OCF 雖然不在這些組織內部，仍能透過四種方式，協助組織建立開源治理能力。

## 轉譯、連結、陪伴與能力移轉

**轉譯**：把國際上的開源經驗、標準與社群方法，整理成臺灣的組織比較容易理解和採用的做法。

**連結**：協助組織接觸適合的社群、專案與開源資源。

**陪伴**：透過課程、工作坊與實作，陪著參與者盤點手上已有的資源、釐清目前遇到的困難，找出可以先採取的下一步。

**能力移轉**：合作一段時間後，組織裡有人可以接手，相關經驗也能留下來。

這四種方法來自 OCF 這幾年與企業、政府合作的現場。我們陪著組織準備開源治理、導入開源軟體，也持續把實際工作中累積的方法、工具與經驗整理下來。

## 讓不同部門先有一段共同經驗

[「開源星手村」桌遊](https://ocf.tw/p/openstarter/)也發展成企業的體驗課程。參與者在遊戲裡扮演具備不同專長的角色，在有限資源與變動需求下，以協作方式完成任務。這段共同經驗提供具體情境，讓不同部門的人更容易看見彼此遇到的問題，也知道該從哪裡開始談。

OCF 去年完成[《開放原始碼良善治理手冊》](https://ocf.tw/story/ospos-1-join-OSPO-alliance/)的在地化翻譯，並依照手冊提出的五個核心面向，設計盤點資源與跨部門協作的學習單，帶著參與者思考如何處理企業內部的開源治理議題。

在協助數位發展部推動開源軟體在地化時，OCF 除了處理介面翻譯，也協助參與的公務人員理解開源專案、回報問題、提出修改與貢獻的方法，逐步建立參與上游社群協作所需的基礎觀念。

這些經驗也延伸到[《公部門開源軟體應用參考手冊》](https://ocf.tw/p/pmpc/)的製作。我們將 OpenChain、授權合規、安全治理等議題，與採購要求、軟體生命週期等內容一併納入手冊，提供公務機關參考。

## 制度可以從一次具體協作開始

**今天的分享留下幾個結論。**

* 開源治理的困難往往超出單一工具能處理的範圍。組織需要先建立共同的協作流程，也要處理不同部門之間的文化落差。

* 一份厚厚的政策文件無法取代共同經驗。大家先知道彼此在擔心什麼，也有共同語言可以討論，制度才有機會從實際工作中逐步建立。

* 組織還沒有正式 OSPO，也可以先做 OSPO 會做的事。從盤點現況、建立討論方式，到完成一次具體協作，這些工作現在就能開始。

從準備、協助 OSPO 成立的角度，OCF 協助組織看見既有的開源能力，進行連結和實作，讓經驗逐步留在組織內部，成為能夠持續運作的能力。如果你的組織也正面對類似問題，歡迎與我們聯繫。
